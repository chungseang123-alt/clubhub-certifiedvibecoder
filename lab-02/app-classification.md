# Lab-02 · Classification of five applications
Version 2.0 · 2026-04-11 · Team: certifiedvibecoder

| # | Application | Kind | Type(s) | Where the code runs, how it is delivered | Architecture | Top 3 qualities (why) | Filled by |
|---|-------------|------|---------|------------------------------------------|--------------|-----------------------|-----------|
| 1 | Mobile banking app: ABA | Applicaion Software | Mobile native; web app; cloud service; data-intensive | Clients run on their phones, either IOS or Android, delivered through official app stores. Backend banking logic runs on the bank's secure cloud servers. | **Client-server** : mobile app communicates via secure APIs with the backend servers, which connect to core banking database. **Evidence** : Account balances, transactions, and transfer cannot be processed offline and require a network connection.| **Security** : hacks could allow attackers to steal users' money and private financial information. **Availability** : if the app goes down, people can't pay for things or transfer money in times of emergency. **Reliability** : bugs could cause wrong account balances or charge payment twice. | Seng Sarak |
| 2 | Telegram |Application software |Mobile cross-platform; desktop; web app; cloud service; data-intensive |Phone and desktop clients delivered through app stores or official downloads; browser client delivered through URL; Telegram servers through server-side deployment. Some messages/media are cached on devices.| **Client-server** : apps exchange cloud chats through Telegram servers. **Evidence**: a cloud chat can appear on multiple signed-in devices after synchronization. Secret Chats behave differently though since they are device-specific.|**Security**: compromised accounts could reveal private conversations. **Availability**: an outage could stop time-sensitive group coordination. **Performance**: delayed message delivery could make urgent communication ineffective. |Sok Chungseang |
| 3 | ABS controller in a car | Embedded software | Embedded; real-time; safety-critical; runs inside the car's control unit (ECU); no user interface | Installed in the car's ECU as firmware by the manufacturer; updated only at a service centre. | **Embedded control loop**: It is a standalone controller: wheel-speed sensors send data to the ECU, and the ECU controls the brake valves. **Evidence**: it works without internet or a user account, and it starts automatically when the car is turned on. |**Security**: if the firmware or diagnostic port is attacked, the braking behaviour could be changed. **Availability**: if the ABS controller fails, the wheels can lock during hard braking and the driver loses control. **Performance**: it must react within milliseconds, because a delay can make the car skid. | Pheng Sopheak |
| 4 | Moodle at ITC | Application software | Web MPA (server-rendered pages); enterprise (learning management system); data-intensive | Runs in the browser (delivered by URL) and on ITC's Moodle server (PHP application with a database). Students and teachers need no installation; an optional Moodle mobile app is delivered through app stores. | **Three-tier**: browser, web/application server, database. **Evidence**: every page is generated by the server, and courses, submissions and grades are stored in the database, so nothing works without a connection. | **Availability**: if Moodle is down during an online quiz, students cannot submit and the quiz must be rescheduled. **Security**: if grades or quiz questions leak or can be altered, exam integrity and student records are compromised. **Performance**: at assignment deadlines hundreds of students log in at once, and a slow server causes failed or late submissions. | Oeung Keangheang |
| 5 | Game: Mobile Legends: Bang Bang | Application software | Mobile native; game; online multiplayer; cloud-based | Runs on Android and iOS smartphones and connects to game servers. Downloaded from Google Play Store or Apple App Store. | **Client-server** : the smartphone runs the game client, while game servers manage multiplayer matches and synchronize player actions. **Evidence** : players must connect to game servers to participate in online matches with other players.  | **Performance** : low FPS or high network latency could make players unable to react quickly during battles. **Availability** : server outages could prevent players from joining matches. **Security** : account theft could result in losing access to accounts, purchased items and game progress. | Song Panhaseth |

Biggest difference we found: The ABS controller is a hard real-time embedded system that must react within milliseconds with no network, no user and no internet connection, and its failure can cause physical harm. The other four (ABA, Telegram, Moodle, Mobile Legends) are networked client-server applications where delays of a second or two are tolerable and failure means lost money, data, or convenience rather than safety.
