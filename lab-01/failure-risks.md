# Failure risks · ITC Club Hub (v0.1, 2026-17-10)
| # | How the project could fail | Chapter 01 topic | Early warning sign | First countermeasure | Owner |
|---|----------------------------|------------------|--------------------|----------------------|-------|
| F1 | Business rule logic (e.g., checking if cancellation is within 24h or if a club is approved) is duplicated across CLI handlers and CSV parsers, leading to inconsistent enforcement. | essential difficulties (invisibility) | Business rule validations appear in both `src/main.cpp` and `include/clubhub/` files simultaneously. | Enforce a single validation function per business rule within `namespace clubhub` and back it with unit tests. | Oeung Keangheang |
| F2 | Poor team communication across the 5 developers leads to broken feature integrations and unresolvable merge conflicts during Sprint demos. | scale and communication | More than 2 unmerged feature branches remain stale on GitHub for over 48 hours without pull request activity. | Schedule brief standups once a week, enforce strict PR review guidelines, and rotate the Scrum Master role each sprint. | Seng Sarak |
| F3 | Business rules shift late in the semester (e.g., adding complex waiting list logic into C++ storage), resulting in massive rework costs right before Sprint 1. | changing requirements and cost of change | Changes are made directly to core C++ domain classes without updating `problem-statement.md` scope boundaries. | Freeze domain model requirements after week 5 and treat waiting lists strictly as a secondary "Should" feature. |Pheng Sopheak |
| F4 | Real student personal data (Student IDs, names, emails, phones) is accidentally committed in a test CSV file to the public repository. | reliability, security and safety | Real student records or test `.csv` files show up in `git status` output before commits. | Add `data/` and `*.csv` to `.gitignore`; populate test suites strictly with anonymized synthetic mock data. | Song Panhaseth |
| F5 | The C++20 build breaks on clean machines or CI due to missing compiler flags or inconsistent CMake layouts across operating systems. | legacy, integration and technical debt | `cmake --build` succeeds on one developer's machine but fails on another or during GitHub Actions build testing. | Standardize `CMakeLists.txt` using target C++20 features and set up `.github/workflows/ci.yml` early to verify builds automatically. | Sok Chungseang |
